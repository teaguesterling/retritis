# lackpy — local-model micro-inferencer

**lackpy** translates natural-language intent into a restricted Python
program (the "lackpy language" — a strict AST whitelist) generated by a
local 1.5B-14B model, validates it, and runs it with traced tool calls.
The intent is to offload routine multi-step tool composition from Claude's
context window to a local small model that's good enough for the
mechanical parts.

When a task is "find files matching X, then for each, do Y, then aggregate
Z," reach for `delegate` instead of doing all of it via Claude's tool
loops. Claude pays one MCP call; lackpy does the N rounds against its own
toolbox, then returns the result.

## When to use lackpy

| Pattern | Use |
|---|---|
| "find files matching X and count Y" | `delegate(intent, kit=...)` — one call, N tool round-trips inside |
| "for each commit in last week, do Z" | `delegate` — small-model loop offloaded |
| "compose a small tool program for this" | `generate(intent)` — get the program without running it |
| "validate this lackpy program" | `validate(program)` |
| "execute this validated program" | `run_program(program)` |
| "what kits / toolboxes / providers are configured?" | `kit_list` / `toolbox_list` / `provider_list` |
| "set up lackpy / what model is in use?" | `config` |
| "explain the lackpy language" | `language_spec` |
| "find docs for tool X in lackpy's docs index" | `docs_index` / `resolve_doc` |

## When NOT to use lackpy

- **Single-shot tool calls** — if the task is one MCP call, just make it directly. Lackpy's value is in N-round composition.
- **Non-mechanical reasoning** — anything requiring judgment, novel design, or recovery from ambiguous tool output should stay in Claude's loop. Lackpy is for the routine parts.
- **Tasks involving tools lackpy's toolbox doesn't expose** — check `toolbox_list` first.

## Core tools

### The main verb
- `delegate(intent, kit?, provider?)` — natural-language intent → generate program → validate → run → return result. The everyday call.

### Lower-level building blocks
- `generate(intent, kit?)` — generate the program text without running it (use for previewing or debugging)
- `validate(program)` — check a program against the AST whitelist
- `run_program(program)` — execute a pre-validated program with traced tool calls
- `create(...)` — create a new program / kit / config object (see implementation)

### Configuration + discovery
- `config()` — show / update the active lackpy configuration (provider, model, kits, sandbox settings)
- `provider_list()` — list configured inference providers (Ollama endpoints, etc.)
- `kit_list()` — list available toolkits (named bundles of tools lackpy can use)
- `kit_create(name, tools)` — create a new toolkit
- `kit_info(name)` — show what tools a kit exposes
- `toolbox_list()` — list every tool lackpy's runtime can invoke (across all kits)
- `language_spec()` — show the lackpy language definition (the AST whitelist)

### Docs
- `docs_index()` — index of available docs
- `resolve_doc(query)` — resolve a docs query

## Workflow patterns

### Quick delegation (the everyday case)
```
delegate(intent="find all *.py files modified in last week and count their lines",
        kit="filesystem,git")
# → returns aggregated result, no tool round-trips for Claude
```

### Preview before running
```
1. generate(intent="...", kit="...") → program text
2. validate(program) → ok/errors
3. run_program(program) → result
```

### Inspect setup
```
1. config() → which provider/model/kits are active?
2. kit_list() → what kits are available?
3. toolbox_list() → what individual tools can lackpy reach?
```

## Tips

- **Best local model:** `qwen3:14b-iq4xs` (per project memory, not `qwen2.5-coder:1.5b`)
- **Kit selection matters** — pass only the kits the task needs. Fewer kits = smaller prompt = faster + more reliable generation.
- **If `delegate` is over-generating** (program too complex / fails validation), drop to `generate` to inspect, then `validate` + `run_program` separately so you can iterate.
- **Tracing** — `run_program` traces tool calls; useful for debugging "why did delegate return X?".
- **The language is strict** — `validate` will reject Python that isn't in the AST whitelist. If you're hand-writing programs, check `language_spec` first.
